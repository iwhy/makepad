# shader_ops.rs — 运算操作编译

**源码路径:** `platform/script/src/shader_ops.rs`  
**总行数:** 640 行  
**核心职责:** 将 Splash 字节码中的算术运算（`+`、`-`、`*`、`/`等）、比较运算（`==`、`!=`、`<`、`>`等）、逻辑运算（`&&`、`||`）以及复合赋值运算（`+=`、`*=`等）翻译为目标后端着色器代码。

---

## 核心架构

所有运算方法均遵循相同的两阶段模式：
1. **弹出操作数**：从 `self.stack` 弹出操作数值字符串和类型信息
2. **类型推导**：通过 `type_table_*` 函数（位于 `shader_tables.rs`）推导结果类型
3. **格式化为目标后端字符串**：使用 `write!` 宏生成带括号的表达式字符串
4. **推回结果**：将结果字符串和类型推回 `self.stack`

---

## 方法详解

### `handle_not` — 逻辑非/位取反（第16-51行）

弹出操作数后根据具体类型生成不同的代码：
- **`bool`** 类型：生成 `(!expr)`（逻辑非）
- **`i32` / `u32`** 类型：生成 `(~expr)`（按位取反）
- 其他类型：报错，说明 shader 中的 `!` 只支持 bool、i32、u32

### `handle_neg` — 一元负号（第53-65行）

弹出操作数并生成 `(-expr)` 或 `(+expr)`（根据传入的 `op` 参数）。结果类型通过 `type_table_neg` 推导。

### `handle_eq` — 相等/比较运算（第67-145行）

处理 `==`、`!=`、`<`、`>`、`<=`、`>=` 等比较运算符。从栈上弹出两个操作数，通过类型表 `type_table_eq` 推导返回类型（通常是 `bool`）。

**整型→浮点隐式提升处理**（第117-141行）：对 GLSL 和 Rust 后端，当操作数一侧是 `AbstractInt`（或 i32/u32）而另一侧是浮点类型时，将一侧转换为浮点字面量（如 `2` → `2.0`）或通过 `(expr as f32)` 语法转换。这是因为 GLSL/GLSL ES 不允许在比较运算符中混用整数和浮点数。

### `handle_logic_test` — 逻辑运算短路处理的第一阶段（第150-170行）

Splash 解释器中的 `&&` 和 `||` 有短路求值语义（通过跳转字节码实现）。但在着色器编译器中，由于没有运行时控制流切换的开销问题，两个操作数都需要被求值。此方法：
1. 弹出第一个操作数（已被之前的字节码计算并压栈）
2. 计算目标 IP（当前 IP + 跳转偏移量）
3. 压入 `ShaderMe::LogicOp` 标记，保存 `target_ip`、操作符（`&&`/`||`）、第一个操作数的值和类型

### `handle_logic_phi` — 逻辑运算的第二阶段：合并（第173-236行）

当执行流达到 `LogicOp` 标记的 `target_ip` 时，从 ME 栈中弹出该标记并与第二个操作数（已由后续字节码计算并压栈）合并。生成 `(first_op && second_op)` 或 `(first_op || second_op)` 字符串，通过 `type_table_logic` 推导结果类型。

此方法使用 loop 处理嵌套逻辑运算在同一点归并的情况，同时注意跳过非 `LogicOp` 的控制流 ME（如 `IfBody`、`ForLoop` 等）。

### `handle_arithmetic` — 算术运算（第238-312行）

处理 `+`、`-`、`*`、`/` 等算术运算符。`is_int` 参数区分整数算术（`type_table_int_arithmetic`）和浮点算术（`type_table_float_arithmetic`）。

**直接内联常量优化**（第246-252行）：当右操作数是 `u32` 类型的 `opargs`（内联常量）时，直接格式化为字符串而不经过栈弹出。

**GLSL/Rust 浮点字面量处理**（第267-286行）：与比较运算类似，对 GLSL/Rust 后端将 `AbstractInt` 字面量在浮点上下文中转换为 `.0` 后缀形式。

**HLSL 矩阵乘法特殊处理**（第288-304行）：HLSL 中 `A * B` 对矩阵类型不直接对应线性代数矩阵乘法（HLSL 中 `*` 是逐分量乘），因此当任一操作数是矩阵类型时，生成 `mul(A, B)` 调用。

### `handle_arithmetic_assign` — 复合赋值运算（第314-386行）

处理 `+=`、`-=`、`*=`、`/=` 等复合赋值。流程：
1. 弹出右操作数值
2. 弹出左操作数，必须是 `ShaderType::Id` 类型（即一个变量名）
3. 在 `shader_scope` 中查找该变量，确认它是可变的 `var` 而非不可变的 `let`
4. 通过类型表验证左右操作数的兼容性
5. 生成如 `var_name += value` 的字符串，将结果类型设为 `void`（赋值表达式在 shader 中不产生值）

此方法也支持参数（`Param`）的复合赋值，参数名称通过 `backend.map_param_name` 映射。

### `handle_arithmetic_field_assign` — 字段复合赋值（第388-544行）

处理 `instance.field += value` 形式的结构体/向量字段复合赋值。从栈上依次弹出：右操作数、字段 ID、实例表达式。根据实例类型分派：

1. **`ShaderType::Pod`**（第408-463行）：在 Pod 类型中查找字段类型，验证复合赋值的结果类型与字段类型匹配，生成 `instance.field += value`
2. **`ShaderType::PodPtr`**（第465-516行）：指针类型（如 Metal 中的 uniform buffer），使用 `->` 语法：`ptr->field += value`
3. **其他类型**：报错

字段名通过 `backend.map_field_name` 映射以处理后端特定的命名约定。

### `handle_arithmetic_index_assign` — 索引复合赋值（第546-639行）

处理 `array[index] += value` 形式的数组元素复合赋值。从栈上依次弹出：右操作数、索引、数组实例。流程：
1. 通过 `type_table_elem_type` 确定数组的元素类型
2. 验证索引类型是整数（`AbstractInt`、`i32`、`u32`）
3. 验证复合赋值的结果类型与元素类型匹配
4. 生成 `instance[index] += value`
